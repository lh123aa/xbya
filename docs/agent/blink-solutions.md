# 眨眼动效：位置不准的根因与可选方案

> 结论先行：**问题不在"哪个位置"，而在"用像素修补头部"这条路本身**。
> 128px 画布上整只眼睛只有 **13×11 = 143 像素**，任何在后处理阶段
> 画补丁/压扁/采样的做法都会露出破绽。要彻底解决，得**换材料**（见方案 3/4/5）。

---

## 一、根因：可用像素太少

实测（`resources/sprites/xbya/idle/frame_001.png`，画布 128×286）：

| 项 | 数值 |
|---|---|
| 左眼框 | **13 × 11 = 143 px**（其中虹膜暗像素 61 px = 43%） |
| 右眼框 | **15 × 11 = 165 px** |
| 闭眼线可用高度 | 约 **3~4 px** |

真人闭眼时，上眼睑要**下落约 11px**、盖住 61 个虹膜像素，同时
**边缘还要与周围皮肤无缝**（颜色渐变 + 抗锯齿）。在 143 个像素的预算里，
这两件事基本无法同时做到 —— 这就是为什么"位置怎么调都不对"。

---

## 二、已经试过的 7 种做法（全部失败，附实测）

| # | 做法 | 实测结果 | 失败原因 |
|---|------|---------|---------|
| A | 肤色椭圆补丁（现行） | 与脸颊色差 **14.1** | 常量色 + 硬边 → 一眼看出**一块米色椭圆** |
| B | 眼区纵向压扁到 15% | 下边界跃变 0.40（好） | **虹膜仍可见**，只是被压扁 → 像**眯眼**不像闭眼 |
| C | 从眼上方取一条皮肤拉伸 | 色差 **141.9** | 采样带进了**眉毛与头发** |
| D | 上下眼皮对合 | 下边界跃变 0.40 | 同 B，**虹膜还在** |
| E | 下凸弧眼睑 + 逐列肤色 | 色差 132.4 | 逐列采样仍取到**发丝**，出来是**竖条纹** |
| F | E + 宽羽化 | 色差 133.7 | 同上 |
| G | E + 双段睑线 | 色差 131.8 | 同上 |

**A/B/D 的复核图（源图放大 3 倍）**：
- A：一块**扁平米色椭圆**浮在脸上，颜色偏黄灰、边缘是硬曲线
- B/D：**眼睛看上去是睁着的**，只是形状怪 —— 因为虹膜没被盖住
- C/E/F/G：**竖向条纹**（采样带进了眉毛/头发）

> 这些图留在 `docs/agent/evidence/p5/_blink_methods.png` 与
> `_blink_methods2.png`，可直接对照。

## 三、可选方案（按推荐度排序）

### ★★★ 方案 1：**素材层解决 —— 要一张闭眼立绘**（最彻底）

让画师/AI 出图时**多给一张闭眼版**（其余构图、光照、姿势完全一致）。
两张图叠起来做差，直接得到"睁→闭"的精确差值，眨眼就是**逐像素真实的**。

- **优点**：100% 准确，无任何人工痕迹；顺带解决"张嘴/闭嘴"表情
- **成本**：一次出图；`make_pet_sprites.py` 加一个 `src_closed` 字段即可
- **改动量**：小（新增 `lm` 之外的一个图片路径 + 一个 blend 函数）

### ★★★ 方案 2：**用 AI 补一张闭眼图**（成本最低的等效方案）

拿现有立绘做 **inpainting**（只把眼睛区域涂掉重画成闭眼）。
本地无 GPU 也能用在线 API（如 Gemini / 即梦 / Stable Diffusion inpaint）。

- **优点**：不用重画整张，改动最小，效果与方案 1 等同
- **成本**：一次 API 调用
- **风险**：重绘区域与周边的接缝需检查（但它是**在原图内重绘**，
  比后处理补丁自然得多）

### ★★ 方案 3：**放弃逐帧画眼，改用"整眼替换"**

从**同一张源图**里裁出眼睛，纵向缩到 25% 后**只贴回眼框内**，
并且**四周用原图的皮肤像素做一圈 2px 的羽化过渡**。

- 与已试的 B 的区别：B 是压扁后**贴在原位**导致虹膜残留；
  本方案是**压扁 + 强制覆盖 + 羽化边**，虹膜会被真正盖住
- **优点**：不需要新素材
- **缺点**：仍然是合成，13px 尺度下需要仔细调参；**优先级低于方案 1/2**

### ★★ 方案 4：**不做眨眼，改做"整头微动 + 表情"**

既然 143 像素画不出可信的眨眼，就**不画**。用已有的、可信度高的动作替代：

- 呼吸起伏（已实现）
- 头部微摆 / 点头（已实现）
- 随机插入 `happy` / `stare` / `think` 等**整帧切换**（这些是全画布动作，天然可信）

- **优点**：零风险，观感立刻变好；且**用户不会觉得"她在瞪眼"**
- **缺点**：少了"活物感"的一个细节

### ★ 方案 5：**提高画布分辨率**

把 `canvas_w` 从 128 提到 192 或 256，眼睛变成 ~20×17 或 ~26×22，
后处理补丁才有施展空间。

- **优点**：根治"像素不够"
- **缺点**：帧数不变但每帧变大（188 帧 × 4 倍面积），
  内存/绘制开销上升；`pet_size` 也要跟着调；且**未必能解决**——
  眼睛变大后，人工补丁的**不自然**同样会被放大

### ★ 方案 6：**用 shader / 运行时合成**（架构级）

不在预渲染帧里画眨眼，而是在**渲染时**对眼睛区域做一个
squash 变换（GPU 上做，边缘用双线性插值）。

- **优点**：分辨率无关、可做平滑动画
- **缺点**：需要改渲染管线（当前是纯 PySide6 贴图，无 shader 通道），
  **改动面最大**，与"桌面宠物低功耗"目标也有冲突

## 四、推荐路径

```
立即做：方案 4（撤掉眨眼，保留呼吸+点头+整帧表情）
        —— 零风险，观感立刻不别扭

本周做：方案 2（AI 补一张闭眼图）
        —— 一次 API 调用，彻底解决，改动小

可选：  方案 1（让出图时直接多给一张闭眼版）—— 如果还要换立绘
暂不做：方案 5 / 6（收益不确定，改动面大）
```

**为什么建议先撤掉眨眼（方案 4）**：
现在的实现即使位置调准，也仍是"一块合成出来的色块"。
在一个 143 像素的眼睛上，**没有眨眼比有一个假眨眼更好** ——
用户反馈的"位置不对"本质是"这个东西看着就是假的"。

---

## 五、如果坚持要有眨眼：方案 2 的落地步骤

1. 用在线 inpainting 把 `avatar_new.webp` 的双眼区域重绘成闭眼，存为
   `resources/source/avatar_closed.webp`
2. `make_pet_sprites.py` 的 `xbya` profile 加一个字段：
   ```python
   "src_closed": ROOT / "resources" / "source" / "avatar_closed.webp",
   ```
3. 新增一个 `blink_by_blend(base, closed, box, alpha)`：
   只在眼框内按 `alpha` 混合两张底图 —— **不做任何形状推断**
4. `f_idle` 的眨眼帧改调 `blink_by_blend(..., alpha=1.0)`，
   过渡帧用 `alpha=0.5`
5. 验收判据（脚本化）：
   - 闭眼帧眼区**虹膜暗像素 = 0**（现在 A 方案还有残留）
   - 闭眼帧与脸颊的色差 **< 5**（现在 14.1）
   - 眼框四边的色差跃变 **< 3**

## 附：已排除的做法（不必再试）

- ❌ 调眼框坐标（试了 5 轮，最好也只能到"位置大致对"，问题不在位置）
- ❌ 换补丁颜色（鼻梁/额头/脸颊都试过，都会露出色块）
- ❌ 从眼周采一条皮肤做填充（必带眉毛或头发 → 竖条纹）
- ❌ 压扁眼区（虹膜盖不住 → 像眯眼）
