## 一、项目目标（一句话）

把 Agent 层从**"自动化全绿"**推进到**"真人与真环境验证过、且改坏了能退回去"**：
先建立可回滚的版本控制，再消掉唯一一个会让用户被骗的功能缺口（提醒重启即丢），
最后把"必须人来做"的验收压成一份照做即可的执行包。

## 五、逐项验收标准（代码化，不写"应该没问题"）

> 每个任务都必须满足项目既有**完成定义**：①`py_compile` 通过 ②对应测试通过
> ③全量回归零失败 ④覆盖率保持项目口径 100% ⑤关键流程手动/端到端验证。
> 下面是**该项特有**的验收条件。

### P4-A1 版本控制

| 验收条件 | 判定命令 / 方法 |
|---------|----------------|
| 已是真正的仓库 | `git rev-parse --is-inside-work-tree` → `true`；`.git` 是**目录**（现为指向不存在路径的指针文件，须先删除该文件再 `git init`） |
| 首提交含全部源码 | `git ls-files \| grep -c '\.py$'` ≥ 164（110 源 + 54 测试） |
| 工作区干净 | `git status --porcelain` 输出为空 |
| **提交内容无明文密钥** | 暂存内容扫描 `gsk_[A-Za-z0-9]{20,}` / `sk-or-v1-[A-Za-z0-9]{20,}` → **0 命中**；`config.yaml` 在 `.gitignore` 中，仓库提供 `config.yaml.example` |
| 忽略规则正确 | `data/`、`__pycache__/`、`*.db`、`logs/`、ASR 临时音频**未入库**；`docs/agent/evidence/voice/fixtures/*.wav`（625KB，属证据）**入库** |
| 可回滚 | `git stash list` 为空；`git log --oneline` ≥ 1 行；改动后 `git checkout -- <file>` 能还原 |

### P4-A2 提醒持久化（D13）

| 验收条件 | 判定方法 |
|---------|---------|
| 落盘 | 新建提醒后 `data/agent_reminders.json` 存在且是合法 JSON（原子写：temp + `os.replace`） |
| **跨进程恢复** | 测试里"写 → 丢弃对象 → 新建 store 加载"后 `pending()` 仍返回该条 |
| 到点仍触发 | 恢复出的提醒到点后仍发 `EventTypes.REMINDER_DUE`（复用 F7 已验证的调度器路径） |
| 不落用户目录 | 落盘路径不在四白名单目录内（与记忆库同规则） |
| 不吞异常 | 文件损坏 / 权限失败 → 降级为纯内存 + 日志，**不抛异常**（沿用 `MemoryService` 的"永不抛异常"约定） |
| 覆盖率 | 新增 store 文件 100%（项目口径） |
| 端到端 | `tools/verify_f7_real_services.py` 增加"跨进程持久化"断言，总数由 27 → ≥29 |

> **实现注意（已核对代码）**：`agent/tracker_store.py` 的 `TrackerStore` 与 `EntityTracker`
> **强耦合**（`load_into(tracker)` / `save(tracker)`），**不能直接复用该类**；
> 应复用它的**原子写套路**（临时文件 + `os.replace`）另建独立 store。
> 文档原先写"复用 `tracker_store.py` 的原子写 + 启动恢复"——指的是**套路**，不是**类**。

> 这条修正本身就是"文档里的面也要核"的实例。

| 不误报（性质） | HTTP 500 与连接异常**不得**被报成配额问题 | ✅ |
| 不泄密 | 状态里不含 api_key（它会被打进日志/状态输出） | ✅ 有用例断言 |

## 八、监督执行机制（这是"监督"的具体含义，不是口号）

1. **门禁不可跳**：每完成一个任务，必须跑 P4-G1/G2/G3；**任何一项回退即停下修好再继续**，不允许"先往后做、回头一起修"。
2. **一次提交一任务**：P4-A1 完成后，每个任务的完成定义里包含"提交信息带任务编号"，便于回滚与 bisect。
3. **绿色必须可复现**：不接受"我这儿跑过了"——所有结论要有 `docs/agent/evidence/p4/` 下的原始输出。
4. **不许凑绿**：断言放宽 / 加屏蔽 / 改判据 / 用假件，都必须在文档里显式登记（沿用 §16.4 与缺陷 19~22 的处置标准）。
5. **未做到就如实写"缺什么"**：P2 项与外部依赖项允许不闭环，但禁止写成通过。
6. **每轮收口时更新**：`tasks-p4.json` 的 `status`、`AGENTS.md` 的债务表、本文件的任务表三处同步。基础状态：
   `P4-A1 done → P4-A2 done → P4-A3 done` 之后，P4 才可宣称"可以给人用"。
