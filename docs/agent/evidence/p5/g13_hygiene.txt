# P5-AUDIT 证据：G13 证据路径检查改为自动发现 tasks*.json

## 一、为什么改

原实现里 task 文件清单是**写死的四个名字**（`tasks.json` / `tasks-p2.json` /
`tasks-p3.json` / `tasks-p4.json`）。P5 新增 `tasks-p5.json` 后，这份清单**没有包含它**：

- 关卡照样报绿（18/18）；
- 而 `tasks-p5.json` 里的证据路径**一条都没被查过**，且没有任何提示。

这与 §16.4 漏登记 `# pragma: no cover` 同族：**沉默失明**。
检查本身必须能发现「有新东西没查」，否则"全绿"只说明"查过的那些没问题"。

## 二、改法（不放宽任何判据，只把清单换成自动发现）

| 改动 | 说明 |
|------|------|
| glob 自动发现 | `docs/agent/tasks*.json`，排序保证输出稳定 |
| 加下限自检 | 「找到 ≥4 份阶段任务清单」—— 文件名被改、被搬走、glob 写错都会红 |
| 字段语义更准 | `evidence` = 已留档（G13 查它）／`planned_evidence` = 打算留到哪（不查） |

**为什么不是"放宽检查"**：未完成任务的计划路径确实还不存在，让关卡一直红的结果是
"红久了就被无视"。正确做法是让**字段语义**更准 —— 这样"把一条任务标 done"就有了
可检查的含义：**证据必须先从 `planned_evidence` 挪进 `evidence`**，否则关卡不会绿。
这是一条把"完成定义"接进关卡的改动，方向与"放宽"相反。

## 三、改造前后计数（两次都能逐条核对）

- **改造前**：18 项，`tasks-p5.json` 不在清单里 —— 既看不到「通过」也看不到「跳过」，
  即"新阶段完全没被查"这件事在输出里**没有任何痕迹**。
- **改造后**：20 项（多出的两项是「找到 ≥4 份清单」与「tasks-p5.json 证据路径」），
  逐条输出见下。
