 一、问题 1：模型为什么从 cat 变成 AvatarSample_A
──────────────────────────────────────────────────────────────────────────────

这不是我「猜」的，是**应用日志自己说的**：

- 切换后的那次启动，日志报 `配置文件加载失败: while scanning a double-quoted scalar
  in "config.yaml", line 105, column 22`，随后 `3/5 初始化插件系统` 一路用**默认值**跑完，
  并连打 5 次 `配置文件保存成功`。
- `core/config_manager.DEFAULT_CONFIG` 里的 `ui.vrm_model` 是 `assets/vrm/cat.vrm`；
- 而真正的 `config.yaml`（与 `config.example.yaml`、README）里写的是
  `assets/vrm/AvatarSample_A.vrm`。

⇒ 崩溃那次**读失败 → 回退默认值 → 存回磁盘**，于是显示的是 `cat.vrm`；
   配置修好后读到了真值 `AvatarSample_A.vrm`，就「变」了。
   **不是形象被改动，而是它本来就配的是 AvatarSample_A。**

（为什么 `config.yaml` 会读失败：`prepare_manual_acceptance.py init` 用双引号包了
 Windows 路径，`\U` 被当成 Unicode 转义 —— 详见 `g8_quota_skip.txt` 之外的
 单独记录，属另一个缺陷。）

 二、问题 2：朝向写死 180°（**产品缺陷**）
──────────────────────────────────────────────────────────────────────────────

`assets/vrm/js/app.js:298-299`（改动前）：

```js
// 让角色正面朝向镜头：VRoid 常默认面向 -Z，相机在 +Z，故绕 Y 转 180°
try { vrm.scene.rotation.y = Math.PI; } catch (_) {}
```

注释里的「VRoid 常默认面向 -Z」**对 VRM 1.0 成立，对 VRM 0.x 不成立** ——
VRM 0.x 的正面是 **+Z**。而 `assets/vrm/` 里两种格式都有：

| 模型 | 规范 | 正面 |
|------|------|------|
| `AvatarSample_A.vrm` | VRM 0.x（VRoidStudio-0.14.0 导出） | **+Z** |
| `chibi.vrm` | VRM 0.x（同为 VRoidStudio 导出） | **+Z** |
| `cat.vrm` | VRM 1.0 | −Z |
| `chibi_handmade.vrm` | VRM 1.0（模型名「小忆Chibi」） | −Z |

⇒ 一律转 180°，**必然把其中一半的模型转成背对镜头**。
   这就是「背身」的直接原因（0.x 模型被多转了 180°）。

 三、问题 3：静态 JS 没有缓存失效（**产品缺陷**）
──────────────────────────────────────────────────────────────────────────────

改完 `app.js` 之后，我加的那行诊断日志
`console.log('[petX] 面向修正 yaw=...')` **在应用日志里完全没出现**。

排查发现：`ui/pet_window.py` 只给 **模型路径** 加了防缓存时间戳：

```python
_query.addQueryItem('_t', str(int(time.time() * 1000)))   # 只影响 ?model=
```

而 `viewer.html` 引的静态脚本是**裸相对路径**：

```html
<script src="./js/bridge.js"></script>
<script type="module" src="./js/app.js"></script>
```

⇒ QWebEngine 沿用缓存的旧 `app.js`。**表现是「改了 JS 却完全没生效」，
   而服务端文件、`py_compile`、grep 全部显示正确** —— 极难排查。

修法：`viewer.html` 改为动态注入脚本，并把 Python 已经传过来的 `_t`
拼到脚本地址上（`./js/app.js?t=<_t>`）。这样「改了 JS 立刻生效」不再依赖
用户手动清缓存。

 四、问题 4：AvatarSample_A 接不上猫的动画
──────────────────────────────────────────────────────────────────────────────

`app.js` 的 `makeBoneBook()` 要的骨骼：

```
hips / spine / chest / upperChest / neck / head
leftUpperArm / leftLowerArm / rightUpperArm / rightLowerArm
+ 名字里含 tail 的骨骼（尾巴）
```

这是**为猫写的**动画系统（要尾巴）。日志里的佐证：

| 模型 | 日志中的模型标识 | 表情数 |
|------|-----------------|--------|
| `AvatarSample_A.vrm` | `name=unknown` | 13 |
| `cat.vrm` | `name=VRM1_Constraint_Twist_Sample` | **18** |

`AvatarSample_A` 是 Unity 官方示例人形（`AvatarSample_A`），**没有尾巴**；
骨骼名对不上 → 动画接不上 → **保持默认姿势**，
也就是用户看到的「双手举过头」（T-pose 变体）。

### 关于 `ui.vrm_yaw_deg` 的取值

**这一项我没有唯一确定** —— 依据是分歧的：

- 规范说 VRM 1.0 正面朝 −Z（`cat.vrm` 属 1.0）⇒ 转 180 该是对的；
- 但 `cat.vrm` 的 `head` 骨骼静止四元数算出 **绕 Y +90°**，
  `Face` 网格顶点又全在 **+Z 侧**（z ∈ [0.038, 0.077]）——
  骨骼旋转与网格偏移叠加后的最终朝向，**光靠读数据算不准**。

所以我把它做成可配项，用**实际渲染结果**来定，而不是继续推理。
当前值：**0**（在 `cat.vrm` 上试）。
