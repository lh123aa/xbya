# 精灵图交接规格 —— 给我什么样的图能用

> 这份文档回答一个问题：**画好的形象，要满足什么条件才能接进桌宠动起来。**
>
> 所有数字都是**实测**的（脚本 `evidence/p5/_tmp_measure_sprites.py`、
> `_tmp_sprite_template.py`），不是估计。判据对着「程序怎么加载」来定，
> 不是审美偏好 —— 不满足就是真的接不上。

---

## 一、现有精灵图的实测规格（这是参照基准）

| 项 | 实测值 |
|----|--------|
| 动画数量 | 10 个：`idle` `listen` `talk` `think` `happy` `sad` `dance` `sleep` `stare` `wander` |
| **帧画布** | **128×128**（10 个动画全部统一） |
| 帧格式 | PNG，RGBA（带 alpha） |
| 角色包围盒 | x[38..89] y[4..99] → **宽 52 × 高 96** |
| 角色占画布 | **宽 41% × 高 75%** |
| 头部区域 | y[4..35]，即**画布上方 32px** |
| 透明像素占比 | 78.3%（背景全透明） |
| 显示尺寸 | `ui.pet_size` = 127px（≈ 1:1，不缩放） |

参考图：`evidence/p5/_sprite_template.png`
（绿=安全区、蓝=角色包围盒、红=头部区域，底下半透明的是现有猫的帧）

## 二、关键发现：动画是**整幅重画**的，不是局部改

实测 `talk` 动画前 6 帧的像素差异：

| 帧 | 变化像素 | 变化范围 |
|----|---------|---------|
| `frame_002.png` | 856 | x[38..89] y[4..99] |
| `frame_003.png` | 1045 | x[38..89] y[4..100] |
| `frame_004.png` | 1232 | x[38..89] y[4..100] |
| `frame_005.png` | 1286 | x[38..89] y[4..100] |
| `frame_006.png` | 1321 | x[38..89] y[4..100] |

**变化范围覆盖整个角色** ⇒ 现有动画是**每帧完整重画**的，
不是「只改嘴」那种局部替换。

这条直接决定了交接要求：

- **只给一张图做不出动画。** 最多能让它静止显示。
- 想让它说话/眨眼，要么给**多帧**（同一角色、同一位置、不同口型/眼型），
  要么给一张底图 + 我能精确定位五官（那我就能自己做局部替换）。

## 三、硬要求（不满足就接不上）

| # | 要求 | 为什么（对着程序说） |
|---|------|---------------------|
| 1 | **PNG 带透明背景**（alpha） | 程序按 alpha 合成到桌面上；白底图会显示成一个白方块 |
| 2 | 角色**高占画布 50%~95%** | 太小看不清，太大会被窗口裁掉 |
| 3 | 角色**水平居中**（左右留白差 < 15% 画布宽） | 换帧时角色会左右跳，看起来像抽搐 |
| 4 | **所有帧角色位置一致** | 同上；位置不一致 = 每帧都在抖 |
| 5 | **正面或接近正面朝前** | 背面/侧面做不了眨眼与口型 |
| 6 | **眼睛与嘴完整可见**，不被头发遮 | 这两个部位是动画要改的地方 |
| 7 | 画布**方形**、**等比例** | 程序按固定尺寸逐帧换图，比例不同会变形 |
| 8 | 分辨率**≥ 128×128**（推荐 512×512） | 低于 128 会糊；大于 128 我来缩 |

## 四、按「你能拿到什么」分三种情况

### 情况 A：你只有**一张**画好的上半身图

**能得到**：静止的桌宠形象（能显示、能拖动、能点，但不会动）

**我要做的**：抠图 → 缩到 128×128 → 居中 → 接进程序

**你需要给的**：一张 PNG（透明背景优先；白底也行，我用 `rembg` 抠）

### 情况 B：你给了**一张底图**，且五官清晰（推荐）

**能得到**：会眨眼、会说话的桌宠（`idle` 静息 + `talk` 说话两套）

**我要做的**：抠图缩放 → **在底图上局部重绘眼与嘴**生成多帧
（闭眼、半闭、张嘴/闭嘴等）→ 组装成帧序列

**你需要给的**：一张正面、五官清晰、不被头发遮的上半身 PNG

> ⚠️ 这条路我要**局部重绘**。我做的是几何形状替换（用肤色/发色填出闭眼线、
> 用唇色填出口型），风格接近原图但不保证完全一致。
> 如果你希望动画帧也是画师画的，就按情况 C 给。

### 情况 C：你给**成套的多帧**（最好）

**能得到**：完整 10 个动画

**你需要给的**：同一角色、同一位置、同一尺寸的多张 PNG，按动画分组，例如：

```
idle/  frame_001.png ... frame_0NN.png     （静息，建议 ≥ 12 帧）
talk/  frame_001.png ... frame_0NN.png     （说话口型循环，建议 8~20 帧）
```

帧数不必和现有猫一样（猫是 20~36 帧），**循环顺畅就行**。

## 五、我会先跑校验，不合格会直接告诉你

图发来后我会先过这几条（脚本 `_tmp_sprite_template.py::check_sprite`）：

- [ ] 有 alpha 通道，透明像素占比 > 5%
- [ ] 角色高占画布 50%~95%
- [ ] 角色水平居中（左右留白差 < 15%）
- [ ] 不是全透明空图

**不合格我会说清哪条不过**，而不是硬接上去再出问题 ——
那样你看到的会是「接上了但怪怪的」，比直接说不能用难查得多。

（该校验器已用现有猫的 3 帧自检通过，确认判据没写歪。）

## 六、完整链路（谁做什么）

| 步骤 | 谁做 | 产出 |
|------|------|------|
| 1. 画形象 | **你**（AI 绘图工具或画师） | 上半身立绘 PNG |
| 2. 规格指导 | 我 | `角色规格书.md`（已交付） |
| 3. 抠图 / 缩放 / 居中 / 对位 | **我** | 128×128 透明 PNG 帧 |
| 4. 做动画帧（眨眼/说话） | **我**（情况 B）或**你**（情况 C） | 多帧序列 |
| 5. 接进程序 | **我** | `resources/sprites/<角色名>/` + 配置 |
| 6. 验收 | **我** | 跑 `run_acceptance.py` 确认没弄坏别的 |

## 七、别给的几种图（明确说清）

| 不要给 | 原因 |
|--------|------|
| 白底/杂色底的 JPEG | 抠图边缘会脏，缩到 128px 后发黑 |
| 全身像 | 缩到 128px 后头只有十几像素，五官看不见 |
| 侧脸 / 背影 | 做不了眨眼与口型 |
| 多人或带场景的图 | 抠不出单个人物 |
| 带水印/文字的图 | 会一起进精灵图 |
| 只有一张且五官被头发遮住 | 只能静止显示，且脸看不清 |
