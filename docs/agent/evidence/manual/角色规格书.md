# 角色规格书 —— 上半身卡通形象

> **这份文档是什么**：把用户提供的照片特征**量准并整理成绘图指令**，
> 供 AI 绘图工具或画师使用。
>
> **这份文档不是什么**：它**不是形象本身**。画图这件事本项目的 AI 助手做不了
> （环境里没有图像生成模型）。文档里不含任何由 AI 生成的角色图像。
> 早期我曾尝试「用代码画」，产出见 `evidence/p5/_bust_sheet.png` ——
> 那版是几何多边形拼的，棱角明显、比例生硬，**不足以作为成品**，仅作过程留档。

| `hair_mid` | `#2E2426` | ~ 参考 | 头发中间调 / 发束分界 |

| `skin_shadow` | `#C1A69A` | ~ 参考 | 颈部 / 下巴阴影 |
| `blush` | `#E59F93` | ~ 参考 | 腮红 |

| `dress_shade` | `#BBBEBB` | ~ 参考 | 裙褶阴影 |
| `eye_iris` | `#4A3226` | ✗ 推断 | **照片里眼睛太小，取色不可靠**，按观察取暖褐 |
| `eye_deep` | `#120C0A` | ✗ 推断 | 瞳孔 |
| `lips` | `#CB8478` | ~ 参考 | **唇框保留比例仅 21%**，量出的 #DBB9A5 偏肤色，此处按观察压红 |

**取色方法**（可复现）：OpenCV `haarcascade_profileface` 检测人脸定位（不靠目测坐标）→
各部位小框多点采样 → 迭代剔野值（每轮以中位色为中心，剔除 RGB 距离 > 38 的像素）→
取中位色。脚本：`evidence/p5/_tmp_bust_palette.py`。

⚠️ **三个值是推断，不是测量**：`eye_iris` / `eye_deep` / `lips`。
   照片里眼睛太小、嘴唇被高光冲淡，取色不可靠。
   **对外陈述时不要把推断说成测量结果。**

**只能当硬约束的是这三个**：`hair_base` · `skin` · `dress`。其余作为风格提示。

## 二、形象特征描述（按照片）

| 部位 | 特征 |
|------|------|
| 发型 | **长卷发，过胸**；中分略偏，两侧波浪下垂；额前有**斜分刘海**，不厚重 |
| 发色 | 近黑，带一点暖褐（强光下可见棕色反光） |
| 脸型 | 鹅蛋脸，下巴略尖 |
| 眼睛 | 黑褐色，眼神温和；**偏大**（卡通化时可按比例放大） |
| 眉 | 细、平缓、颜色与发色同系 |
| 妆容 | 淡；唇色自然偏红；脸颊有淡腮红 |
| 服装 | **白色无袖连衣裙**；V 领；上身有细密竖纹（抽褶/肌理布）；腰部以下为层叠裙摆 |
| 姿态 | 站姿，双手自然背在身后（画上半身时手可省略或轻收入身后） |
| 氛围 | 温和、安静、清爽 |

## 四、生成时必须满足的**工程约束**

这几条不是审美偏好，是**为了能接回桌宠程序**。不满足的话，图再好看也用不上。

| # | 约束 | 为什么 |
|---|------|--------|
| 1 | **只要上半身**，腰部以上 | 桌宠窗口是竖长条，全身会缩到看不清 |
| 2 | **正面或接近正面**朝前 | 程序靠正面像做眨眼/说话的帧替换；侧脸改不了眼和嘴 |
| 3 | **背景纯色或透明** | 要抠图当精灵；杂乱背景抠不干净，边缘会碎 |
| 4 | 头发**不要大面积压住肩线** | 同上，发梢与背景交界处最容易抠碎 |
| 5 | 眼睛与嘴**清晰可辨、不被头发挡** | 这两个部位是动画要单独替换的 |
| 6 | 分辨率 **≥ 1024×1280** | 最终显示只有 127px，但要多帧缩放，源图太小会糊 |
| 7 | 一次生成**同一角色多张**（≥6 张） | 要从里面挑一张眼/嘴位置规整的做动画底图 |

### 推荐生成参数

| 项 | 建议 |
|----|------|
| 画幅 | 竖构图 4:5 或 3:4 |
| 采样步数 | ≥ 25（太低线条会断） |
| CFG / 引导强度 | 7~9 |
| 批量 | 6~8 张，挑一张 |
| 若支持 ControlNet / 参考图 | 用照片做 **face/pose 参考但只取大形**，强度调低（0.3~0.5），否则会画成照片风 |

## 五、验收清单（成品拿到手先过这几条）

- [ ] 是上半身，腰部以上，没有全身
- [ ] 正面朝前，两眼与嘴都完整可见、没被头发遮住
- [ ] 背景是纯色或透明，边缘干净
- [ ] 发色 / 肤色 / 裙色与配色表对得上（目视近似即可）
- [ ] 没有水印、文字、签名
- [ ] 分辨率 ≥ 1024×1280
- [ ] 头部在画面上方约 1/3 处，留出下方肩与衣服

不合格就别往下走 —— 拿回去重生成，比后面修补便宜得多。

## 六、成品接回桌宠的路径（这部分我可以做）

图拿到后，交给本项目 AI 助手，可以做这些：

1. **抠图**：环境里有 `rembg`（已装），把背景去掉得到透明 PNG
2. **裁切与缩放**：按 `ui.pet_size`（当前 127）缩放到合适尺寸
3. **做动画帧**：在底图上**局部替换**眼与嘴的位置，生成
   眨眼 / 说话口型的多帧 —— 这是 2D 精灵动画的通行做法，
   本项目 `resources/sprites/cat/` 那 10 个动画就是这个结构
4. **接进程序**：替换 `resources/sprites/<角色名>/` 下的帧，
   或新增一个角色目录，让 `animation.controller` 加载
5. **验收**：跑 `tools/verify_gui_launch.py` 与 `tools/run_acceptance.py` 确认没弄坏别的

> ⚠️ 第 3 步有个前提：**底图的眼与嘴位置要规整**（正面、对称）。
> 所以上面「工程约束」第 2、5 条必须满足，否则动画做不出来。

## 七、能力边界（如实记录）

- 本项目 AI 助手**不能生成图像**：环境里没有 `diffusers`、没有模型权重。
  早期尝试过两条替代路径，都失败并已留档：
  · **代码搭 3D VRM** → `gen_chibi_vrm.py` 生成的模型**不做蒙皮**
    （0 个 skin、47 个网格全是静态），骨骼驱动不了它，装不上。
    留档：`evidence/p5/vrm_facing.txt`
  · **代码画 2D 插画** → 几何多边形拼出来的图棱角明显、比例生硬，
    达不到可用品质。留档：`evidence/p5/_bust_sheet.png`
- 因此**画形象这件事必须由外部工具或人完成**。这份规格书就是为此准备的中间产物。
- 规格书里的描述来自照片的**客观特征与取色**，不含任何「AI 想象中的长相」。
