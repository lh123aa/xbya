P4-B1 证据：事件总线契约守护（D14）
====================================
日期：2026-09-11
任务：docs/agent/tasks-p4.json §P4-B1

【零】本轮处置的**边界**（先说清，避免被读成"B1 全做完"）
--------------------------------------------------------------
`p4-plan.md` 给 B1 列了三条验收条件，其中第二条（"`app.agent_bus` 与 pipeline
使用的事件契约由**同一个类型**约束，**或**经适配层转换且断言双向可达"）
有两种实现路径：

| 路径 | 改动面 | 风险 |
|------|--------|------|
| A. **守护 + 显式拒绝**（本轮采用） | 只加 `assert_kernel_bus` 与测试；**不动**任何调用方的契约 | 低 —— 不改语音管线 |
| B. 加适配层把两个总线统一 | 会动到 `core/app.py`、`services/voice_service.py` 等受 G12 保护的语音路径 | 高 —— `p4-plan.md` §六 与 §八「能力边界」把"是否接受该改动面"列为**人工决定** |

**本轮只做 A。** 理由有两条且都是计划里写明的：
① 计划把 B 的改动面交给人工决定（我不该替用户接受一个会碰语音管线的架构变更）；
② A 恰好堵住的是**真正造成过事故的那个洞** —— 事故的形态不是"契约不统一"，
而是"接错了却不报错"。

所以 B1 本轮的结论是：**"静默降级"这一半已关闭；"统一契约"那一半待人工决定。**

【一】事故复盘（为什么"显式拒绝"才是关键）
--------------------------------------------------------------
两个同名不同契约的 EventBus：

| 类 | 订阅 | 发送 | handler 收到 | 事件类型 |
|----|------|------|-------------|---------|
| `core.event_bus.EventBus` | `subscribe(EventType, h)` | `emit(EventType, data: dict)` | 未验证（本轮未走这条） | 枚举 |
| `core.kernel.events.EventBus` | `on(str, h) -> disposer` | `emit(str, source="", **data)` | **一个 `Event` 对象（位置参数）** | 字符串 |

历史事故：`core/app.py::_setup_agent_layer` 把前者传给了只认后者的 Agent 层 →
`pipeline.start()` 里 `bus.on(...)` 抛 `AttributeError` → 被那一层的 `except` 吞掉
→ **Agent 层在整个真实应用里一直是死的**（静默降级为纯对话），
而所有脚本级验收各自 `new` 内核总线，**全都测不出来**。

一句话：**降级可以接受，静默降级不可接受。** 这与 P4-B3 处理的
"引擎缺 `chat_with_tools` → 路由兜底静默失效"是同一类事故。

【二】本轮实现
--------------------------------------------------------------
`agent/bootstrap.py::assert_kernel_bus(bus)`：

- 检查 `on` / `off` / `emit` 三个方法**可调用**（三者在，契约就够用）
- 不通过则抛 `TypeError`，错误信息里：
  · 列出**缺哪些方法**
  · 报出**收到的类全名**（`type(bus).__module__` + `__name__`）
  · 若它有 `subscribe`，**点名"你传的看起来是 `core.event_bus.EventBus`"**，
    并写出两者契约的差别与后果
- `None` 单独给一条信息（"请传 `core.kernel.events.EventBus`"）
- 接在 `build_agent_stack()` 的**最前面**（第 0 步）——
  放在入口而不是做成"可选的工具函数"，否则下一个接线的人不会调它

**只检查契约、不检查具体类**：`AgentStack` 的测试替身不该被迫继承真实类
（有用例钉住这一点）。

【三】反方向验证（检查本身不许空转）
--------------------------------------------------------------
`tests/agent/test_eventbus_contract.py` **12 项**，两个方向都覆盖：

| 方向 | 用例 |
|------|------|
| 放行 | 内核总线通过；鸭子类型的等价契约对象也通过 |
| 拒绝 | 旧总线被拒；`None` 被拒；缺 `off` 的对象被拒 |
| 信息质量 | 错误信息必须同时出现 `core.event_bus.EventBus`、`core.kernel.events.EventBus`、`subscribe` |
| 装配入口 | 传旧总线给 `build_agent_stack` → `TypeError` 且含"契约不符"；传对的总线照旧装出 21 个工具 |
| 契约差异被钉住 | 旧总线有 `subscribe` 无 `on`；内核总线有 `on` 无 `subscribe` —— 将来若有人统一它们，这些断言会红，**强制那次改动是有意的** |

> **我自己的测试被真实契约推翻一次**：我按 `handler(**kwargs)` 写了断言，
> 跑出来才发现内核总线的 handler 收的是**一个位置参数 `Event` 对象**
> （`events.py:160 handler(event)`）。改成实测契约后 12/12 通过。
> 顺带把 P3 踩过的坑也钉住了：`emit(t, source="x", value=7)` 里
> `source` **不进 `data`**（它是 `emit` 的第二个形参）——
> 这正是当时事件负载里没有计划来源、测试读 `started["source"]` KeyError 的原因。
