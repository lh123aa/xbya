【一】测量口径（重要：分开报三类结果）
--------------------------------------------------------------
`measure_asr_stimulus.py --short N`：对 6 句各合成 N 次，交**项目自己的 ASR 插件**转写，
按三类分别计数：

| 类别 | 含义 | 该改哪儿 |
|------|------|---------|
| HIT | 正识 | — |
| 空输出 | 整句被丢（VAD 判静音 / 短词门槛拦掉） | ASR 侧门槛与 VAD |
| 听错 | 出了字但不对（「散了」） | 解码偏置 or 路由侧 |

把"空输出"与"听错"混成一个"命中率"就看不清该修哪一层 ——
与 C4 里"反爬 / 解析器 bug / 网络不通"必须分开是同一条纪律。

命令：python tools/measure_asr_stimulus.py --short 4
（voice=zh-CN-XiaoxiaoNeural，asr=small —— 与归档回环同一口径）

【二】基线（无偏置）
--------------------------------------------------------------
[不稳] '算了'      正识 0/4   空输出 0   听错 4   ← 4/4 次被听成「散了」
[不稳] '不用了'    正识 2/4   空输出 2   听错 0   ← 2/4 次整句被丢
[OK  ] '停止'      正识 4/4   空输出 0   听错 0
[OK  ] '取消'      正识 4/4   空输出 0   听错 0
[OK  ] '确定'      正识 4/4   空输出 0   听错 0（输出「確定」，繁简归一化后命中）
[OK  ] '确认'      正识 4/4   空输出 0   听错 0（1 次输出「確認」）

合计：**正识 18/24，空输出 2，听错 4**

两个缺陷性质不同：
· 「算了」→「散了」是**确定性听错**（4/4），不是替身抖动。
· 「不用了」→ **整句被丢**是另一类问题（短词门槛 / VAD），与听错无关。

【四】副作用测量：偏置会不会把**别的话**拉成确认/取消语
--------------------------------------------------------------
只报"正识率上升"是不够的：偏置是"让某些词更容易被解码出来"，
而被误拉成「确定」的代价是**执行一个用户没批准的删除**。

对照句（都不是确认/取消语），偏置 ON：

  '你好呀'         -> ['你好呀!', '你好呀', '你好呀', '你好呀!']
  '今天天气怎么样'   -> ['今天天气怎么样', '怎么样', '今天天气怎么样', '今天天气怎么样']
  '打开浏览器'      -> 4×['打开浏览器']
  '讲个笑话'        -> ['想的笑话', '讲个笑话', '讲的笑话', '想的笑话']

**ASR 层没有被误拉**：4 句的转写都还是原话（「讲个笑话」有 2 次把"讲"听成"想"，
但不影响意图）。16 次里 0 次被解码成确认/取消词。

⚠️ 但脚本第一版把这 16 次里的 4 次报成了"被拉成确认/取消语" —— **那是假的**：
判据用的是产品的 `CONFIRM_PHRASES`，而其中含单字「好」，
`'好' in '你好呀'` 为真。也就是说**测量工具把一个产品缺陷当成了偏置的副作用**。
查清之后才发现真正的缺陷在路由侧（见第五节）。这条与 §17.3 的教训同源：
**测量工具自己也会造假红/假绿。**

【五】★ 顺带抓到的危险缺陷：待确认时一句招呼被当成「确定」（已修）
--------------------------------------------------------------
根因：`RuleRouter._matches_any` 原是朴素子串匹配 `if p in text`，
而 `CONFIRM_PHRASES` 含**单字「好」**、`CANCEL_PHRASES` 含**单字「否」**。

真实 `RuleRouter`（`has_pending_confirm=True`）实测：

| 用户说 | 修前 | 后果 |
|--------|------|------|
| 「你好呀」 | **confirm** | 一句招呼 → 放过待确认的 `file_delete` |
| 「我很好」 | **confirm** | 同上 |
| 「好奇怪」 | **confirm** | 同上 |
| 「好久不见」 | **confirm** | 同上 |
| 「你是否在听」 | **cancel** | 用户只是提问，待确认项却被撤掉 |

`confirm` 是**唯一会直接把用户推进副作用**的路由分支（它会放过删除），
对应 AGENTS.md 的 R1「误操作损坏文件」——项目最高优先级风险。
修前 20 条用例错 5 条；**修后 0 条**。

修法（写进 `_matches_any` 的 docstring，作为契约）：
**确认方向从严、取消方向从宽**。四个出错方向的代价完全不对称：

| 出错方向 | 代价 |
|---------|------|
| 误判成 confirm | **直接放过待确认的删除**（用户没批准的事被执行） |
| 误判成 cancel | 待确认项被撤掉，用户再说一遍（无损） |
| 漏判 confirm | 待确认项挂着，用户再说一遍（无损） |
| 漏判 cancel | 待确认项挂着，用户以为取消了（B5 的原始抱怨，非破坏性） |

- 严格档（confirm，`strict=True`）：剥掉标点后短语命中，且**剩余字符只能是
  语气助词或单字应答**。
- 宽松档（cancel，默认）：多字短语子串命中（保住「我不要了」这类真实说法）。
- **单字短语在两种档位都不做子串匹配**，必须整句成立。
- 语气助词表只收真正的话语标记（呀啊哦呃吧啦呢嘛哈哟噢唉诶那的咯喽），
  **绝不收「是 / 对 / 行 / 不」这类实义字** —— 收进来会立刻把缺陷引回来。

过程中我自己的第一版修法**被自己的测试推翻一次**：
只做"单字整句 + 多字子串"时，「这不太好吧」（一句反对）因为含子串「好吧」
被判成 confirm。于是才改成上面的宽严分档；剩余集里允许"别的单字应答"
是为了保住「好的，删吧」这种复述式确认（它仍挡得住「这不太好吧」，
因为那里的剩余是「这不太」，全不在允许集内）。
