【一】两处必须澄清的"我差点报错"
--------------------------------------------------------------
1. **上一次我看到的 `exit code 1` 是我自己的 PowerShell 管道过滤器造成的**，
   不是脚本失败。单独复跑确认：`35/35 通过、0 失败、0 跳过`、`exit=0`。
   （教训：**不要在带 `Select-String` 的管道上看 `$LASTEXITCODE`** ——
   管道的退出码未必是被测程序的退出码。）
2. **我第一版截图脚本传了 `path=` 参数，被静默忽略**，于是截图落到了
   `C:\Users\49046\Pictures\Screenshots\`。原因不是产品 bug：
   `ScreenshotTool.params_schema` 只声明了 `filename`，而
   `BaseTool.validate_params` 对**未声明的字段放行（宽松策略）**，
   工具于是用自己生成的名字、存进自己的目录。
   产品的做法本身是**对的**：`execute` 里 `out_dir / Path(name).name`
   刻意剥掉目录部分，正是为了挡住"用 filename 指定任意路径"。
   → 这一条记成**调用方需要注意的行为**（见【三】），不是缺陷。

【二】截图留证：它证明了什么、没证明什么
--------------------------------------------------------------
用产品自己的 `screenshot` 工具抓了一张 1920x1080 真 PNG（141163 字节，PNG magic 正确），
并且**人眼看过**（`read_image`）。看到的事实：

| 观察到 | 说明 |
|--------|------|
| 任务栏出现名为 **「Example Domai…」** 的浏览器标签 | `web_open("https://example.com/")` **确实开起来了**，且打开的是指定 URL |
| 浏览器窗口**不在最前**（最前的是 DSH 窗口） | ⚠️ 所以只能说"**真开了**"，**不能**说"用户会看到它跳出来" |

第二行很重要，而且它与本任务的原始动机一致：
`p4-plan.md` 记这条的起因就是"现默认只断言 URL 正确交给 webbrowser，**避免抢窗口**"。
实测确认该工具**不会把浏览器抢到前台** —— 这既解释了当初为什么不敢断言"真开"，
也说明"真开"与"抢焦点"是两件事，不能混为一谈。
