fix(launcher): 默认启动改为无窗口（新增 启动欣雅.vbs + 失败弹窗）

用户反馈："启动后不要显示后台终端"。

## 根因：两个启动器里，默认那个本来就带黑窗

项目里一直有两个入口，但文件名完全看不出区别，任何人都会去点名字更
直白的那个：

  - 启动欣雅.bat      -> python run.py（控制台版）=> 必然弹黑窗，
                         而且那个窗口一关，程序就跟着退出
  - 后台启动欣雅.vbs  -> pythonw + shell.Run(cmd, 0, False) => 无窗口

真机实测确认：VBS 那条路的进程树是 wscript -> pythonw -> 欣雅，
中间没有 cmd，屏幕上只有桌宠。所以问题不在"缺一个无窗口方案"，
而在默认入口选错了，且文件名没有表达这个取舍。

## 改动

1. 默认入口收敛为无窗口

  - 新增 启动欣雅.vbs —— 双击即静默启动，从自身所在目录推导项目根
  - 启动欣雅.bat -> 重命名为 启动欣雅（看日志）.bat，名字写明它是排查工具
  - 删除 后台启动欣雅.vbs（被 启动欣雅.vbs 取代，避免两个入口打架）

2. 无窗口启动的隐患必须补上：崩了要能看见

pythonw.exe 没有标准输出（sys.stdout is None），任何 print/traceback
直接消失 —— 于是"双击后什么都没发生"成了唯一现象，无从排查。
所以配套做了两件事：

  - run.py 新增文件日志 logs/xbya.log（每次启动覆盖），
    且 StreamHandler 仅在 sys.stdout is not None 时添加
    （否则 pythonw 下会直接抛错）；异常分支额外双保险写文件，
    保证"为什么失败"一定留得下
  - 启动欣雅.vbs 启动后等 6 秒探测进程存活；若已退出，读日志最后
    14 行弹 MsgBox。判据刻意不是"退出码"而是"进程是否还活着" ——
    因为单实例锁会让第二个实例正常退出（退出码 0），那不是故障

3. .gitattributes 同步更新

原来的规则写的是旧文件名，改名后规则失效，Git 会按 core.autocrlf
做行尾转换 —— 正是该文件注释里记的那个坑（GBK 的 .bat/.vbs 被转码后
中文变乱码、启动器整个失效）。已更新为：
启动欣雅.vbs -text / 启动欣雅（看日志）.bat -text

## 验证

成功路径（真机双击 VBS）：
  - 可见窗口只有一个：pythonw 欣雅；无 cmd / conhost
  - logs/xbya.log 正常生成（190+ 行）

失败路径（注入 RuntimeError）：
  - wscript 进程保持存活等你点确定 => 弹窗确实出现了
  - 日志里抓到原始原因：[启动失败] RuntimeError: 故意制造的启动失败
  - 测完已还原 run.py，并核对无残留故障文本

编码保全（改名最容易踩的坑）：
  - 两个文件 git check-attr text 均为 unset
  - 暂存区 blob 大小与工作区逐字节一致（4228 / 2758）

回归：2920 passed / 1 skipped / 0 failed
